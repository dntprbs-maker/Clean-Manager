# 페이지네이션·인증 전환 구현 및 검증

작성일: 2026-11-05. 작성자: 덱시. 상태: 구현·로컬 검증 완료, 운영 전환 검증 진행 중.

## 확정 사항

- 기존 일정·근태·정산 기능을 유지하며 페이지네이션을 적용한다. 머지와 배포까지 승인된 작업이다.
- Android 위젯도 Firebase 인증 세션을 사용하도록 함께 전환한다.
- 최고 운영자는 기존 관리자 아이디 `33`으로 지정한다. 비밀번호는 변경하지 않는다.
- 직원의 전화번호 최초 비밀번호 설정은 유지한다. 전화번호를 아는 사람의 계정 선점 위험도 이 정책에 남아 있다.

## 기존 구조와 변경 결과

| 구분 | 기존 | 변경 |
|---|---|---|
| 일정 | 회사 전체 실시간 구독·클라이언트 전개 | 소유자는 표시 범위·겹침·반복 원본·상세 대상 합집합 구독. 직원은 서버 권한 필터 후 조회 |
| 반복 일정 | 오래된 반복의 반복 횟수 제한으로 현재 회차 누락 가능 | 표시 범위로 직접 이동하여 전개. 이동 예외·원래 회차 식별·양끝 포함 유지 |
| 보고·활동 기록 | 전체 목록 렌더링 | 20건씩 더 보기. 동률 식별자 정렬, 필터와 오래된 문서 호환 경로 유지 |
| 보고 상태 | 부분 목록에서 미보고로 오인 가능 | 관련 보고 확인 전에는 확인 중 표시 |
| 월 수입·정산 | 전체 자료 의존·클라이언트 확정 | 월 자료 전체로 합산하고 행만 나눠 표시. 정산 확정은 서버 트랜잭션으로 재계산 |
| 인증 | 클라이언트 저장값·직접 DB 접근 의존 | 서버 비밀번호 검증 후 회사·계정·버전이 포함된 Firebase 세션. 실시간 계정 상태 재검사 |
| 위젯 | 로그인 없이 DB REST 조회 | 로그인 세션을 전용 저장소에 전달하고 인증된 서버 조회. 로그아웃·회사 전환 시 캐시 분리 |

검색·대시보드·편집·오래된 날짜 필드가 없는 보고서는 기존 결과를 보존하기 위해 필요 시 전체 조회를 사용한다. 직원 서버 조회와 필터 선택지 확인에도 전체 원본 조회가 남아 있다. 따라서 모든 경로의 읽기 비용이 페이지 크기로 제한된다는 의미는 아니다. 비용 절감 수치는 아직 측정하지 않았다.

## 실제 실행한 검증

- 서버 단위·회귀 테스트 89개 통과.
- 반복 일정 범위 테스트 13개 통과. 오래된 매일 반복, 월말·윤년·이동 예외·겹침 포함.
- 에뮬레이터 권한 검사 39개 통과. 익명·타회사 차단, 관리자 직원 관리, 개인 일정·피드 비공개, 직원 수정 범위, 정산 직접 쓰기 차단 포함.
- 실제 Chromium 화면: 활동·보고 목록 20→40→45건, 현재 달의 오래된 반복 표시, 로그인 복원, 직원 개인 일정 분리 통과. 보고 이력은 기존 숨김 메뉴를 유지한 채 테스트에서 화면 경로를 직접 선택했다.
- 실제 정산 화면과 서버 저장 계산 결과 985,000원 일치. 일급·주급·월급·수당·추가지급을 포함한 가상 자료로 확인했다. 실제 송금은 하지 않았다.
- 월 수입 45건 합계 1,044,000원 일치. 20번째 이후 자료도 합계에 포함됨을 확인했다.
- Android 최종 앱·계측 APK 빌드 통과. 연결 기기에서 세션 저장·전환·로그아웃 3개 재검증 통과. 운영 시험 토큰으로 위젯 실제 서버 조회(일반25건+반복30회차), 개인 일정 비공개, 실제 refresh token 갱신, 갱신 후 재조회, 기존 주간 위젯 RemoteViews 레이아웃 렌더링과 이미지 직접 확인, 로그아웃 캐시 숨김 계측1개 통과. 홈 런처에 위젯을 직접 배치하거나 사용자의 실제 계정으로 로그인한 검사는 아니다.
- 프로덕션 빌드 통과. 전체 ESLint는 기존 오류가 있어 통과로 보고하지 않는다.

## 운영 준비 및 미완료

인증 서버·조회·쓰기·정산 API와 필요한 인덱스를 먼저 준비했다. 운영자의 기존 계정 지정, 전화번호 최초 설정 정책, 비밀 필드를 제외한 직원 프로필 16건을 준비했다. 기존 비밀번호와 일정·보고·정산 원본은 변경하지 않았다. 웹과 보안 규칙의 최종 전환은 아직 완료하지 않았다.

운영 자료는 전체 내보내기 대신 컬렉션 개수와 문서 ID 해시를 메모리에서 계산하는 읽기 전용 방식으로 확인했다. 운영 회사 기준 일정 826건·보고 21건이며 기존 자료를 삭제하지 않았다. 기존 보안 규칙 릴리스 참조와 인증 설정 이전값은 저장소 밖 비공개 위치에 보관했다.

운영 자료와 분리된 개발검증 회사·관리자·직원 및 가상 자료 생성은 자동 승인 검토에서 별도 승인이 필요하다고 거절된 뒤, 사용자가 명시 승인했다. 별도 시험 회사에 98건을 생성하고 기존 회사는 변경하지 않았다. 시험 자료는 삭제하지 않고 유지한다. 실제 운영 서버의 관리자·직원 토큰 로그인, 직원 개인 일정 필터, 인증 위젯 조회 및 익명 위젯 차단, 미리보기 일정·보고/로그 20→25건, 정산 화면 985,000원과 서버 확정 저장을 검증했다.

운영 첫 로그인에서 토큰 서명 권한 누락을 발견했다. 기존 런타임 서비스 계정에 자기 자신에 대한 Token Creator 역할만 부여하고 실제 로그인 성공을 재검증했다. 프로젝트 전체·사람 계정 권한을 추가하지 않았다. IAM Credentials API는 이미 활성화돼 있었다. 이전 정책은 비공개 백업에 보관했다. [Firebase 공식 토큰 서명 권한 문서](https://firebase.google.com/docs/auth/admin/create-custom-tokens)를 기준으로 적용했다.

머지 후 운영 도메인의 같은 시험 흐름과 배포된 Rules의 익명·타회사·직원 원본 접근 차단을 다시 확인한다. 실패 시 이전 Hosting 버전과 보안 규칙 릴리스로 복구하고 원인을 기록한다. 별도 Vercel 검사는 무료 일100회 배포 한도 초과로 실패했으며 유료 전환하지 않았다. 실제 사용 Firebase PR 빌드·배포는 통과했다.

## 남아 있는 경계

직원 전체 배정 정보의 급여 필드와 공용 프로필의 일당은 기존 공유 구조가 남아 있다. 별개 attendance 앱의 기존 규칙도 이 작업에서 변경하지 않았다. 이 변경은 전체 저장소·모든 앱의 보안 감사를 완료했다는 의미가 아니다. 세부 감사 결과는 같은 날짜의 보안 검토 JSON에 기록한다.

로컬 검사와 별도 운영 시험 자료의 검증을 구분한다. 운영 전환·머지·배포 결과는 후속 기록으로 남긴다. Android 검증 중 시험 파일 접근이 건너뛰어진 최초 결과는 통과에서 제외하고, 필수 실행 검사와 PNG 형식·이미지 직접 확인 후의 재실행만 위 결과에 포함했다.
