# 직원·위젯 범위 조회 개선

일반 직원 캘린더와 Android 위젯이 매번 회사의 일정 원본 전체를 읽던 동작을 수정한다.

- 직원 화면의 1분 보완 확인은 서버 변경 번호 한 문서만 읽는다. 같은 번호이면 일정·보고서 API를 호출하지 않는다. 재접속 시에도 서버가 권한과 조회 범위를 확인한 뒤 변경이 없으면 기존 화면 자료를 유지한다.
- 일반 일정은 표시 구간의 시작일 조회와 기간 겹침 조회를 합친다. 오래된 반복 원본과 날짜가 이동한 예외를 보존하기 위해 반복 원본은 별도로 읽는다. 멀리 떨어진 선택 날짜는 별도 구간으로 조회한다.
- 보고서는 선택된 일정 ID에 연결된 자료만 읽는다. 기존 보고 상태·작성 이어가기의 의미를 유지하기 위해 해당 반복 원본의 과거 보고서도 보존한다. 이는 기간별 보고서 읽기 상한을 보장하지 않는다.
- 편집·복사·상세 창은 필요한 원본 ID만 추가한다. 전체 검색·대시보드·직원 보고 이력의 명시적 전체 범위 동작은 유지한다.
- 위젯은 유효한 같은 범위의 캐시를 재사용한다. 앱 일정 수정은 캐시를 무효화하고, 사용자의 수동 새로고침은 서버에서 다시 확인한다. 로그인 범위가 바뀌면 이전 캐시를 노출하지 않는다.
- 서버 조회 장애는 재시도 가능한 응답으로 구분하여 정상 로그인 정보를 인증 만료로 처리하지 않는다.

검증: 서버 단위 시험 100개, 로컬 권한 시험 39개, 별도 범위 조회 에뮬레이터 시험, 실제 브라우저 일정·보고 이력·정산·재무 흐름, 직원 변경 번호·별도 구간·편집 원본 조회 흐름을 확인했다. Android 단위 시험과 실기기 격리 인증·캐시 시험 5개를 확인했다. 운영 배포와 운영 화면 검증 결과는 별도로 기록한다.

이 변경은 회사 DB의 모든 전체 조회를 제거하는 변경이 아니다. 일반 캘린더·위젯 경로의 불필요한 조회를 줄이며, 실제 비용은 데이터 분포·권한 확인·겹치는 쿼리·색인 읽기·공유 무료 할당량에 따라 달라진다.
