# 사용자별 문서 읽기 기록

- 적용일: 2026-11-20 한국시간. 과거 사용량의 원인 추적 및 소급 귀속은 하지 않음.
- 운영 반영: 기존 appAuth, appSharedSchedule, appReadData, appWriteData, appAccount, appWidgetData 함수만 변경. 앱 재설치 불필요.
- 기록: 인증된 계정 ID·회사 ID·계정 종류, 요청 시작/종료 시각(UTC 원본), 호출 기능, 관측 문서 읽기 수, 성공/실패. 보고에서는 한국시간으로 표시.
- 보관: 기존 Google Cloud Logging의 clean_manager_read_usage 구조화 로그. 기록을 위해 Firestore 문서를 추가로 읽거나 쓰지 않음. 로그 수집·보관에는 기존 Cloud Logging 과금 정책이 적용되므로 무료 보장을 뜻하지 않음.
- 개인정보: 비밀번호·토큰·일정/업무 본문·문서 경로를 자체 구조화 로그에 포함하지 않음.
- 집계: 문서 get는 존재하지 않아도 1회, 빈 query도 최소 1회, query 반환 문서 수, getAll 문서 수, 재시도된 트랜잭션 읽기를 관측. 동시 요청은 AsyncLocalStorage로 계정을 분리.
- 한계: 관측 문서 읽기이며 청구 확정 수치가 아님. 인덱스 항목 읽기 등은 포함되지 않을 수 있음. 직접 SDK 읽기는 기존 DATA_READ 감사로그에서 사용자와 시각을 확인하며, 서버 공용작업/MCP/예약작업을 특정 사람에게 임의 귀속하지 않음. 단일 계정의 여러 기기는 같은 계정으로 합산되며 실제 사람 수와 동일하다고 단정하지 않음.
- 실패: 인증되지 않은 요청은 계정 미확인으로 남김. 실패한 읽기나 계측 불가 읽기는 확인되지 않은 값을 만들어 채우지 않음.

## 기록 조회

기존 비공개 조회 도구: .pagination-private/collect-user-read-usage.mjs. ISO 시작시각을 인자로 전달하면 구조화 로그만 조회하고 비공개 폴더에 저장한다. complete=false이면 페이지 제한 때문에 전체 집계라고 보고하지 않는다. 요청 수와 문서 읽기 수는 별도 값이다.

관리 화면의 사용자별 일일 통계는 이번 변경에 포함하지 않는다. 기존 .usage-work의 미완성 화면/계측 코드는 보존하며 운영 배포하지 않았다.
