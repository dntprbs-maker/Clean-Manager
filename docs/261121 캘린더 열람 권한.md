# 캘린더별 열람 대상 · 2026-11-21

메뉴 → 캘린더 공유 관리 → 캘린더 펼치기 → 팀과 사람 직접 선택 → 팀/직원 체크 → 열람 대상 저장.
팀은 복수 선택할 수 있고, 선택 팀의 현재 소속 직원 또는 개별 선택한 직원이 열람한다. 회사 관리자와 개인 캘린더 주인은 계속 열람한다. 수정·금액 권한은 기존 역할을 따른다.

설정하지 않은 캘린더는 기존 정책을 보존한다. 선택 대상을 모두 해제하면 회사 관리자와 개인 캘린더 주인만 열람한다. 일정은 이동·복사·삭제하지 않는다. 이번 구현·검증에서 운영 일정은 조회하지 않았다.

선택 정책은 appReadData/appWidgetData, 서버 수정 권한 확인, 별도 공유, 구독 피드 및 일정 내용 알림에 적용한다. 로그인 없는 피드는 선택 정책에서 차단한다. 변경은 온라인 동기화 이후 적용되며 이미 다운로드하거나 외부로 복사한 내용을 회수하는 기능은 아니다.

설정 변경은 appCalendarAccess가 관리자 인증·현재 회사의 팀/직원·버전을 확인하고 캘린더와 readRevision만 원자 갱신한다. 일정 컬렉션은 조회하지 않는다. 조회 변경 번호를 즉시 올려 비동기 트리거 지연 중에도 캐시의 notModified 응답을 방지한다. 일반 직원·관리팀은 raw Firestore 쓰기로 viewAccess를 바꿀 수 없다.

검증: functions/test/calendarAccess.test.js, test/calendarAccess.emulator.mjs, test/calendarAccess.screen.mjs. 실제 UI 체크박스 저장, 선택 직원 로그인, 해제 후 캐시 재조회, 위젯, 타사·수정·권한 우회 차단을 가상 회사 acl_qa에서 검증했다.

로컬 실행은 firebase.acl-qa.json으로 demo-clean-manager만 사용한다. Firestore=8180, Auth=9198, Functions=5101, Vite=5277. 시험 스크립트에는 FIRESTORE_EMULATOR_HOST=127.0.0.1:8180, FIREBASE_AUTH_EMULATOR_HOST=127.0.0.1:9198, FUNCTIONS_EMULATOR_ORIGIN=http://127.0.0.1:5101을 지정한다. 앱에는 VITE_USE_EMULATORS=true, VITE_FIREBASE_PROJECT_ID=demo-clean-manager 및 위 포트를 지정한다. 운영 프로젝트로 시험 자료를 주입하지 않는다.
