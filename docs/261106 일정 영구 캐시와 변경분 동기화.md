# 일정 영구 캐시와 변경분 동기화

웹과 Android WebView는 같은 서버 권한 검사를 사용한다. Callable 응답은 Firestore SDK 캐시에 자동 저장되지 않으므로, 허용된 일정·보고서 응답을 계정·권한·표시 기간별 IndexedDB에 저장한다. 재실행 시 저장된 자료를 먼저 표시하고 서버 확인은 별도로 진행한다. 저장된 자료만으로 정산을 확정하지 않는다.

서버의 변경번호와 비공개 변경 기록을 같은 트랜잭션에서 갱신한다. 전달 ID를 변경 기록의 식별자로 사용해 재전송을 중복 처리하지 않는다. 변경 기록에는 종류·문서 ID·보고서 연결 ID만 보관한다. 일반 일정·보고서 변경 시 변경된 문서를 다시 권한 검사한 후 기존 자료에 합친다. 삭제·기간 이탈·권한 상실은 이전 자료에서 제거한다. 관리자 전체 보고 이력은 원본 일정 삭제 후에도 보존한다.

변경번호가 같으면 일정·보고서 본문을 조회하지 않는다. 새로운 기간, 권한에 영향을 주는 설정 변경, 변경 기록의 공백이나 큰 누적 변경은 해당 범위의 완전한 스냅샷으로 재확인한다. 반복 일정은 원본 하나의 변경으로 회차 여러 개가 달라질 수 있으므로 그 원본의 표시 회차를 함께 교체한다. 같은 날짜에 겹친 이동 회차도 유지한다.

앱 응답에 포함된 위젯 표시 자료와 위젯용 범위 확인 키를 Android 저장소에 전달한다. 앱이 종료된 후 위젯이 직접 변경 여부를 확인하더라도 이 키와 변경번호를 재사용한다. 변경이 없으면 저장된 자료를 유지하고, 있으면 해당 원본의 회차만 교체한다. 푸시는 변경 기록 반영 후 발송해 갱신 신호가 변경 기록보다 앞서 도착하지 않도록 한다. 구 APK에는 지원하지 않는 추가 브리지 필드를 전달하지 않는다.

로그아웃 시 앱의 영구 일정 캐시를 비우고 위젯 세션·캐시도 기존 절차로 정리한다. 계정·권한·기간이 다른 캐시는 섞지 않는다. 네트워크 실패 시 저장된 표시 자료를 유지하며 최신 확인·금액 확정 상태와 구분한다.

검증은 `test/scheduleDelta.emulator.mjs`, `test/scheduleCache.screen.mjs`, `test/scheduleCache.test.js`와 기존 권한·일정·정산 회귀, Android 빌드 및 기기 계측으로 수행한다. 기기 계측과 운영 배포는 별도 실제 실행 결과를 확인해야 완료다.
