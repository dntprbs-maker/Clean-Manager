## 동작

1. 최초 조회에서 변경기록의 확정 순번을 먼저 읽고 일정·팀·보고 원본을 한 번 가져온다. 최초 조회 중 생긴 변경 또는 늦게 도착한 알림은 이후 순번에서 다시 받는다.
2. 서버 트리거는 알림에 담긴 과거 값을 그대로 쓰지 않는다. 트랜잭션 안에서 현재 원본을 다시 읽고, 회사별 순번과 변경기록을 동시에 쓴다. 중복 알림 ID는 기존 기록으로 판정한다. 오래된 알림이 뒤늦게 와도 현재 원본 상태를 기록한다.
3. 2분마다 확정 순번 문서 1건을 확인한다. 새 순번이 있으면 그 구간만 최대 200건씩 읽는다. 모든 페이지를 모은 뒤 허브가 원본·회차·처리위치·정상상태를 같은 SQLite 트랜잭션으로 저장한다. 누락 순번·부분 페이지·잘못된 처리위치는 실패 처리하며 앞당기지 않는다.
4. 반복 원본은 허브에 보관한다. 새 수정이 없어도 매 실행의 날짜 범위에서 회차를 계산한다. 원래 회차 날짜를 식별자에 보존하고 변경·취소·완료·imported 전환·범위 밖 이동은 기존 회차를 물리 삭제하지 않고 표시에서 제외한다.
5. 네트워크 응답만 잃어 같은 반영을 다시 보내도 저장된 요청 지문으로 처리한다. 재시작 때는 저장된 원본과 처리위치로 재개한다.
6. 늦은 알림이 아직 안 보이는 빈 응답은 원본에 변경이 없다는 확정이 아니다(`source_quiescence=unknown`). 다음 주기에 계속 확인한다. 최종 실패·유실 알림 복구용으로 마지막 전체 대조로부터 24시간이 지나면 전체 대조를 별도로 한다. 현재 자료량의 추가 비용은 약 810건/일이다. 평소 2분 확인을 전체 대조로 대체하지 않는다.
7. 원본 변경 경로만 트리거 대상이며 `mcpHubStreams`에 쓰는 기록은 재감지하지 않는다. 기록 TTL/자동 정리·삭제 없음. MCP는 기존 인증으로 고정된 회사만 조회하고 변경기록은 기존 `mcp*` 서버 전용 규칙에 포함된다.
