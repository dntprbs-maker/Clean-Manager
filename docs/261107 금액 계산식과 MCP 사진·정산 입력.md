# 금액 계산식과 MCP 사진·정산 입력

## 동작

- 청소비·팀장 지급액·팀원 지급액·추가 비용과 수입·지출 장부 금액에 `15000×37`, `100000*4`처럼 곱셈식을 입력할 수 있다. 쉼표, x/X/×/*, 소수 평수도 지원한다.
- 칸을 벗어나면 계산한 원화 금액을 표시하고, 다시 탭하면 원래 식을 표시한다. 저장 후 재열기에도 식을 보존한다. 숫자 금액을 원본으로 함께 저장해 기존 클라이언트와 호환한다.
- 미완성 식, 음수, 원 미만 소수 결과, 안전한 정수 범위 초과는 저장하지 않는다. eval/Function 없이 정확한 정수 산술로 계산한다.
- 수입·지출 목록의 항목을 눌러 기존 금액과 식을 수정할 수 있다. 저장이 실패하면 창을 닫지 않고 오류를 안내한다.
- 사진 썸네일을 누르면 큰 사진이 열린다. 두 손가락 확대·축소, 확대한 사진 이동, 초기화, 기본 배율에서 사진 넘기기, 닫기를 지원한다. 확대 중 핀치나 이동은 사진 순서를 바꾸지 않는다.

## MCP

- `get_event_finance`: 청소비·지급액·인원수·단가·추가 비용·손익 조회. 알려지지 않은 지급액은 0원으로 추정하지 않는다.
- `set_event_finance`: 알려준 필드만 수정한다. 다른 필드와 지급상태를 보존하며, 이름/항목별 지급액·비용은 기본적으로 갱신 또는 추가한다. 전체 목록 교체는 명시적인 replace 옵션으로만 수행한다.
- `memberPays:[{headcount:4,unitAmount:100000,status:"paid"}]`로 실제 이름을 임의 생성하지 않고 4명 묶음 지급을 기록할 수 있다. 앱에서 단가/인원 식을 바꿀 때 묶음 메타정보도 맞춰 유지하거나, 더 이상 맞지 않는 정보는 제거한다.
- `attach_event_photos`: 기존 사진을 보존하면서 새 사진을 추가한다. create_event/update_event의 기존 사진 입력도 유지한다. JPG/PNG/WEBP/GIF, 장당10MB·합계20MB, 요청 본문28MB 이하로 제한한다.
- 서버는 인증을 먼저 확인한 뒤 업로드 본문을 읽는다. 사진 파일명은 경로 문자를 정리하고, 내부 저장 경로는 응답에서 숨긴다.
- 정산은 `finance:read`·`finance:write` 전용 권한을 사용한다. 직원·팀 관리의 admin 권한을 함께 부여하지 않는다. 일반 일정 조회에는 정산 권한이 없으면 finance를 반환하지 않는다. 기존 키·OAuth 토큰은 바꾸지 않는다.

## 확인한 범위

- 서버 단위검사130개, 금액/시간/캐시 관련 순수검사8개, 기존 청소비 화면 회귀, 새로운 MCP HTTP→에뮬레이터 DB/사진 저장→실제 앱 화면 종합시험 통과.
- 종합시험은 기존 기본100KB 제한을 넘는 PNG2장 업로드·썸네일 로딩·사진 확대, 지급 내역의 순차 입력과 보존, 금액식 포커스/블러·저장·재열기·불완전식 거부, 장부 수정, 두 손가락 확대 시 페이지배율1 유지와 사진 순서 보존·초기화/넘기기/닫기를 확인했다.
- 변경 파일의 기존 오류와 비교한 신규 lint 오류0, 프로덕션 빌드 통과. 전체 저장소의 과거 lint 오류가 모두 해결됐다는 뜻은 아니다.
- 현재 운영 MCP 소스4개와 origin/main 원문이 같은지 대조한 뒤 변경했다. 기존 원본 작업트리와 선행 미커밋 시험4개는 보존한다.

운영 배포·노트10·연결된 MCP에서의 최종 검증 결과는 작업 원장과 최종 검증 기록으로 보완한다. 실제 회사 자료는 시험하지 않고 승인된 검증 자료를 사용한다. 새로운 DB·외부 서비스·유료 기능을 추가하지 않는다.
